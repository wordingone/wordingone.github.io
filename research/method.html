How I work

Most of the code and most of the experiment runs in these projects were done by AI coding agents. My job is to set the questions, the rules a result must pass, and the review. Because agents are fast and confident, the method is meant to make it hard for a claim to get ahead of its evidence. This page describes that method as the public repositories record it; each part links to where it is written down or used. Most examples come from Ember (pinned to commit df2a2d6).

1. Freeze the test before the run

Each hypothesis in Ember's research log moves through recorded stages (among them observed, explained, predicted, running, measured, ruled and closed). At the "predicted" stage it is required to carry a refutation criterion, written before any number exists. The log states the rule: "a criterion is never amended after the numbers arrive, so the successor freezes its own before it is authored." The log's export currently holds 456 rulings SUPPORTED, 402 REFUTED and 100 INCONCLUSIVE (counted from the export file). The Search judged candidate learners against a written set of constraints, though these were amended once mid-study (May 2026), so they were not frozen in the same sense (The Search).

2. Receipts

A claim counts only if it points to a receipt: a stored record of a run that actually executed. Ember's repo map calls its receipts folder "ground truth for all board verdicts", and the index lists 1,022 rows. The research pages are regenerated from the records and "a validation failure produces no page at all". Not every receipt is public: the research pages name private receipts as plain text rather than links, and this site marks numbers it cannot link.

3. Refusals

The default answer is no. A training checkpoint that a ruling does not accept is refused and credits nothing to the model's lineage. A benchmark score at chance is recorded with "no capability, sufficiency, or comparison claim". A measuring tool that cannot confirm what it measured refuses to report: after the profiling error described on the Ember page, the replacement probe "refuses to census if captured is false".

4. Named successors

When a test fails or a tool turns out to be wrong, it is not quietly patched. A new, named item replaces it, with its own frozen criterion, and the old one stays in the record. For example, a measurement split that did not hold was "frozen in a named successor rather than patched into this instrument"; structured entries carry a successor field pointing to the next hypothesis.

5. Correct the public record

When a claim in a public repository turns out to be stronger than its evidence, the correction is written next to it. In The Search, the line "R3 solved by composition" now carries a note that it is superseded, because the test did not measure a gain in task performance. In gemma-architect, the hackathon write-up is marked a historical draft whose claims were not independently verified.

Limits of the method

In The Search, the review of each experiment was done by agents, "not by independent human reviewers". Frozen criteria stop moving goalposts; they do not make a badly chosen criterion good. None of this work has been peer reviewed.
