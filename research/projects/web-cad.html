WEB-CAD

April-June 2026 (forked from gemma-architect on 2026-05-24). Live: wordingone.github.io/WEB-CAD. Code: github.com/wordingone/WEB-CAD (links pinned to commit c672cb9).

Role: I designed and directed it.

What it is

In the README's words, "a free browser-based experimental CAD workbench" that "runs entirely in the browser: no server, no API key, no install", and is "not a production replacement for Rhino, Revit, or ArchiCAD".

What was built

  • Implemented An in-browser AI agent using Gemma 4 E4B-it through Transformers.js and WebGPU that turns prompts into editable geometry.
  • Implemented NURBS surfaces with IFC4 round-trip export; the README's NURBS code is pure JavaScript.
  • Implemented A separate C++ geometry kernel compiled to WebAssembly (kern/: booleans, fillet, chamfer, loft).
  • Implemented An MCP server that lets coding agents drive the geometry tools.

What was measured

  • Measured C++ kernel against OpenCASCADE: 7/7 box boolean cases matched in volume within 0.1%, and a 60/60 robustness fuzz with no crash. Scope is narrow: box/box booleans only; the NURBS check was skipped, so not verified. The run log the report names is not in the repository.
  • Measured In-browser decode speed: median 2.13 tokens/s (range 1.96-2.23) over 25 prompts on WebGPU, measured on the gemma-architect deployment. The file does not record the hardware.

What is open

The README's known limitations include "AI agent accuracy varies" and that WebGPU is required for the AI. At about 2 tokens/s the live model is slow, and the bundled demos come from a prompt cache rather than live generation (see gemma-architect). Two bundled WebAssembly files have unknown provenance in the third-party notices.
