ember-cli

2026. Part of Ember: code in src/ember/infrastructure/tools/ember-cli. The open-weights mode is on the branch feat/ember-cli-open-weights-mode, not on master and not released.

Role: I directed and reviewed; AI coding agents wrote the code. The branch commit says so: "Code was written by AI coding agents under operator direction and review."

What it is

Ember's README describes it as "the command-line tool used to run and watch the training". It is an agent tool in the terminal (TypeScript on Bun, with a React/Ink text interface): a model reads and edits files, runs shell commands and reports back.

What was built (branch, unreleased)

  • Implemented An open-weights mode that runs a third-party open model (Qwen) downloaded from Hugging Face; "It is not an Ember-trained model". A pull command ranks a built-in list of models and takes the best one that fits free GPU memory, and checks the download's sha256 (commit message).
  • Implemented Saved sessions with resume, automatic context compaction, project instruction files, and a one-command Windows setup (commit message). The branch changes 242 files.

What was measured

  • Observed (one machine) On one 24 GiB RTX 4090, the setup selected a 27B-parameter model at 4-bit (16.4 GiB file) with an estimated 21.2 GiB GPU memory (dry-run example in the install guide). Calibration on that card selected a 131,072-token context by default, and 262,144 with less headroom. The guide states that its hardware table for other cards is "computed, not measured on each card size".
  • Tested Three waves of blind tests run by AI agents (UI, file operations, shell, web, long sessions, computer use) produced the fixes in the branch commit. For the computer-use tests, the agents drove the real terminal window through a console harness, not the operator's mouse and keyboard (commit message, "Testing disclosure"). No pass/fail tally is published.
  • No speed (tokens per second) measurement is published; numbers of that kind in the test files are fixtures, not measurements.

What is open

Findings from the blind tests that are not yet fixed are tracked in three open issues: #2379 (file operations), #2380 (shell) and #2381 (UI/UX and web). One shell finding is that a command which starts a background process on Windows can block until the timeout; the cause is described in the code. #2378 (exiting must stop the model server and free the GPU) is open. The branch has not been merged into master. (Issue states read 2026-11-04.)
